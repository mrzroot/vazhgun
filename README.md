> **vazhgun** (واژگون, "inverted") opens a Persian/Arabic `.docx` and lists where *what you typed* and *what the reader sees* differ: ⁧شکل ۲-۳⁩ drawn as ⁧شکل ۳-۲⁩, a minus that jumps behind its number, left-to-right paragraphs and tables, invisible direction characters. Offline; `--fix` writes an explicit corrected **copy**.

**Contents:** [Why](#-why) · [Install](#-install) · [Quick start](#-quick-start) · [Before / after](#-before--after) · [Features](#-features) · [Rules](#-rules-and-finding-codes) · [How it works](#-how-it-works) · [Limits & honesty](#-limits--honesty) · [Roadmap](#-roadmap) · [Contributing](#-contributing) · [License](#-license)

## 🎯 Why

A hyphen or slash between Persian digits is a *weak* character in the Unicode Bidirectional Algorithm, so which way the chain is drawn
depends on its surroundings: after Persian letters `۲-۳` is drawn in reading order (the first number on the right), at the start of a line or
inside brackets or after Latin letters it is drawn left to right. A thesis that mixes `شکل ۲-۳`, `(۲-۴)` and `Fig. ۲-۳` therefore shows two
different orders on one page, and `-۵` can be drawn as `۵-`. Each of these is a one-line fix once you know where it is. `vazhgun` finds where, and
shows the order explicitly instead of leaving it to the renderer.

## 📦 Install

Python 3.9+, no dependencies. Tested on Linux only.

```sh
pipx install git+https://github.com/mrzroot/vazhgun      # PyPI release not published yet
uvx --from git+https://github.com/mrzroot/vazhgun vazhgun --demo
pip install -e .                                        # from a clone
```

## 🚀 Quick start

```sh
vazhgun thesis.docx                              # audit
vazhgun thesis.docx --json                       # machine-readable (includes the drawn segments)
vazhgun thesis.docx --strict                     # exit 1 on warnings too (default: only on errors); for scripts
vazhgun thesis.docx --fix --chains ltr           # write thesis.vazhgun.docx; number chains explicit, first number on the LEFT
vazhgun thesis.docx --fix --chains reading       # same, first number on the RIGHT (reading order)
vazhgun thesis.docx --fix --strip-controls       # also delete stray embedding/override/isolate characters
vazhgun --demo                                   # generate a synthetic chapter and audit it
vazhgun --make-sample chapter2.docx              # just write that sample file
vazhgun notes.txt                                # .txt/.md: paragraph-level checks only
```

Real output on a synthetic document (excerpt):

```text
$ vazhgun chapter2.docx            # a synthetic chapter generated by `vazhgun --demo`; excerpt
vazhgun 0.1.0 · chapter2.docx · 25 paragraphs (19 Persian), 1 tables

! V203 Sign «-» is drawn after its number   [¶7 · Normal]
    typed: ⁦در شب‌های زمستان تا -۵ درجه‌ی سان⁩
    drawn: ⁦⁧ درجه‌ی سان⁩⁦۵⁩⁧در شب‌های زمستان تا -⁩⁩   (approximate; runs listed left to right)
    why  : In a right-to-left paragraph a hyphen or plus in front of a digit is a weak character that goes with the Persian text around it, so it is d …
    fix  : Put a left-to-right mark (U+200E) before the sign, or use the real minus U+2212 with it. `--fix` inserts the mark.

! V202 Inconsistent drawing of caption / chapter-style numbers (شکل ۲-۳, (۲-۴))   [¶10 · Normal]
    typed: ⁦(۲-۴)⁩
    drawn: ⁦⁧)⁩⁦۲-۴⁩⁧(⁩⁩   (approximate; runs listed left to right)
    why  : 2 of these are drawn left-to-right (first number on the left) and 6 right-to-left (first number on the right) in this document, so the same …
    fix  : Pick one convention for the whole thesis and apply it: `--fix --chains reading` (first number on the right, RLM after the separator) or `--fix --chains ltr` (first number on the left).

[…]

2 error(s), 4 warning(s), 3 note(s); 9 fixable with --fix.
```

(Persian lines are wrapped in invisible isolate marks so they print the same in any terminal; "drawn" lists the runs left to right.
The full, unedited output is in [docs/demo.txt](docs/demo.txt).)

## 🆚 Before / after

The same synthetic chapter in LibreOffice 25.2 (Linux, fallback fonts), before and after `vazhgun --fix --chains ltr --strip-controls`: the page range `۱۵-۱۲` becomes `۱۲-۱۵`, `۵-` becomes `-۵`, and the PDF-pasted paragraph and the table are right-to-left. This is LibreOffice, **not Word**.

In the CLI the same finding reads (real output, a one-line invented `.txt`): the *typed* line `تا -۵ درجه` is *drawn* with the sign behind its number, and `--fix` inserts a left-to-right mark before the sign.

## 🧩 Features

| | |
|---|---|
| 🧭 **Direction audit** | paragraphs and tables with Persian text but no right-to-left setting (`w:bidi`, `w:bidiVisual`), also through styles |
| 👁 **Typed vs drawn** | an approximate drawn view of each flagged line, computed with its own Unicode bidi (UAX #9) implementation |
| 🔢 **Number chains** | caption numbers, page and year ranges, dates: reports when one document draws the same kind of chain in two orders |
| 🛠 **Explicit fix to a copy** | adds `w:bidi` / `w:bidiVisual`, LRM or RLM marks (`--chains`), strips stray controls; other parts of the file stay byte-identical |
| ⚖ **Checked against references** | implementation compared with libfribidi (identical levels on 40,000 random strings) and python-bidi (bracket-free strings) |
| 🔌 **Scripts and agents** | `--json`, `--strict`, exit codes, an `AGENTS.md` snippet |
| 🔒 **Offline** | no network, no AI, no telemetry, no dependencies |

## 🔎 Rules and finding codes

<details>
<summary><b>All finding codes (V101–V203)</b></summary>

| code | severity | meaning | `--fix` |
|---|---|---|---|
| V101 | error | Persian text in a left-to-right paragraph (no `w:bidi`, also through the style) | adds `w:bidi` |
| V102 | info | Latin paragraph set right-to-left | no |
| V103 | warn | table with Persian text but without `w:bidiVisual` (columns read backwards) | adds `w:bidiVisual` |
| V104 | error/info | invisible embedding / override / isolate characters (unbalanced = error) | `--strip-controls` |
| V201 | info | number chain (range, date, caption number) whose order rests on the renderer; consistent in this document | `--chains` |
| V202 | warn | the same kind of chain is drawn in two orders in one document | `--chains` |
| V203 | warn | sign `-` / `+` before a digit is drawn after the number (`-۵` looks like `۵-`) | LRM before the sign |

</details>

## 🔧 How it works

1. Paragraph and table direction is read through the style chain and `docDefaults`; number chains are found by regular expression (digits with `- – / .`) and classified as caption, page range, year range, range or date.
2. The "drawn" line is the Unicode Bidirectional Algorithm as implemented here (checked against libfribidi), listed as runs from left to right. It is an approximation of what a renderer draws, not what Word draws.
3. `--fix` writes a copy; see the details below.

`--chains ltr` wraps every chain in left-to-right marks (U+200E); `--chains reading` puts a right-to-left mark (U+200F) after each separator.
The fixer edits only `<w:t>` text and the `w:bidi` / `w:bidiVisual` properties; every other part of the file is byte-identical, and it
refuses to write if its paragraph count does not match the one the checker saw.

## 🧭 Limits & honesty

- **An audit, not a verdict.** "Drawn" is an approximation; there is no single correct order, and which convention your university wants is a style decision you make.

- **It is not Word.** "Drawn" is the Unicode Bidirectional Algorithm (UAX #9) as implemented here; Word, LibreOffice, Google Docs and PDF export can
  differ. The implementation is checked against libfribidi (identical embedding levels on 40,000 random strings) and python-bidi (bracket-free
  strings only; it disagrees with the standard on bracket pairs). I rendered the demo in LibreOffice 25.2 only. I have **not** verified any of
  this in Microsoft Word on Windows or macOS; a published note by another author reports that Word can draw a slash date day-first where the algorithm
  says left-to-right, and that only an LRM fixes it. That is why V201 says "rests on the renderer" instead of "wrong".
- There is no single correct order. Which convention a university wants (`۲-۳` or `۳-۲`) is a style decision; `vazhgun` reports inconsistency and lets you choose.
  `--chains ltr` (LRM) is the better documented fix; `--chains reading` (RLM after separators) is reasoned from the Unicode algorithm and is less tested.
- Heuristics: chains are found by regular expression (digits with `- – / .`), classified as caption, page range, year range, range or date; decimals, times and IDs are skipped. Text boxes,
  footnotes, headers, comments, content controls and fields other than simple `SEQ` results are not analysed. Explicit embedding/override controls are reported (V104) but not previewed.
- Direction inherited through styles (`basedOn` chain) and `docDefaults` is read; direction set only by a numbering level is not. Text boxes, tracked-deletion text, equations, footnotes and content controls are counted as unsupported and mentioned in the report.
- Not an official university validator, and it does not check margins, fonts or references (see its sibling tools if you need those).
- Offline: no network, no AI, no telemetry. Reads the file you pass and writes only the copy you ask for.
